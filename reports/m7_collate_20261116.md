### 为什么需要这一层

上一轮实现了梯度累积引擎，但它接收的是「已经切好的 micro-batch」。而 `build_supervised_example` 每次只产出**单条**样本，其长度各不相同（实测训练侧完整序列 min 57 / max 468）。要把 8 条长度不同的样本拼成一个 micro-batch，就必须做 padding 与批内对齐——这一步此前不存在。

### 核心风险：本模型 pad 与 EOS 同 ID

`pad_token_id == eos_token_id == 151643`。这带来一个极易写错、且**不会报错、只会静默降低效果**的陷阱：

若用 `input_ids != pad_token_id` 来推断哪些位置有效，那么**每一个真实 EOS 都会被判定为 padding**，于是它的 label 被置 `-100`、mask 被置 `0`——恰好把模型最应该学会的「在此停止」信号屏蔽掉。训练仍会正常收敛到某个数值，只是学不会终止。

因此 `collate_supervised_examples` 全程**只用 `attention_mask` 与 `labels` 判定有效性**，并有一条专门的回归测试逐条断言每条样本监督区间末尾的 EOS 仍然可见。

### 第二个陷阱：两层 padding 叠加

单条样本已按 `pad_to_multiple_of = 8` 补过一次。若在其后直接追加到批宽，就会出现两层 padding，而**中间那层的边界无法从 IDs 恢复**（因为 pad 与 EOS 同 ID，无法区分「它是单条样本的 padding」还是「它是真实 EOS」）。

处理方式：先用 `prompt_token_count + supervised_token_count` 求出**真实有效长度**，把单条样本自带的那层 padding 视为待重建，再从干净的有效区间重新补到批宽。批宽取最长有效长度并向上取整到 8 的倍数。

## 实现要点

`collate_supervised_examples(examples, *, pad_token_id, pad_multiple=8, eos_token_id=151643)`：

| 行为 | 说明 |
|---|---|
| 批宽 | 最长有效长度向上取整到 `pad_multiple`，保证批维度满足论文的形状约束 |
| `input_ids` | 有效区间 + `pad_token_id` 填充 |
| `attention_mask` | 有效区间为 1，padding 为 0 |
| `labels` | prompt 区间 `-100`、监督区间原 token id、padding `-100` |
| 返回类型 | 三个二维**列表**（不是张量），由调用者决定设备与 dtype |
| 副作用 | 无：不写文件、不改输入、不分配显存 |

前置条件（校而不改）：

- 批内 `sample_id` 必须唯一，否则报错——重复 ID 会让后续按 ID 对齐的评分与去重逻辑失效。
- 单条样本自带的 padding 必须自成一段（mask=0 且 labels=-100），否则说明上游边界已被破坏，直接拒绝而不是在批组装时静默修正。
- 未截断的样本，监督区间必须以 EOS 收尾；**用 labels 判断而非 ids**，理由同上。

已截断的样本允许存在，其有效区间即为截断后的长度。
